## Overview

CoffeeShop.Admin is a standalone **Blazor WebAssembly** (.NET 8) admin panel for a coffee shop: dashboard/reports, orders, products (menu items, categories, toppings, recipes), ingredient inventory, promotions, and accounts. All UI text, comments, and docs are in **Vietnamese**; keep new UI strings and code comments in Vietnamese to match.

## System context

This repo is one part of a team-built coffee-shop management system. Each part is owned by a different sub-team; only the web admin lives here:

- **Backend** (other team): ASP.NET Core Web API (IIS Express / Kestrel) + SQL Server database. This app's `Services/` call it.
- **Tablet app** (other team): Flutter. Customers pick items and place orders on the tablet.
- **Web admin** (this repo, our team): Blazor WebAssembly. Owner and staff manage the orders placed from tablets, plus menu, inventory, promotions, accounts and reports.

Core flow: tablet creates order (`POST api/v1/don-hang`, no token) → backend stores it as `PENDING` → web admin sees it (the Orders page always auto-refreshes every 3 s — there is deliberately no on/off toggle; SignalR push is planned in `docs/ke-hoach-dong-bo-thoi-gian-thuc.md`), takes payment (`POST api/v1/don-hang/{id}/thanh-toan`, backend deducts stock via `sp_ThanhToanVaTruKho`) or the owner cancels it (`POST api/v1/don-hang/{id}/huy` + reason). Two independent statuses: payment `PENDING`/`PAID`/`CANCELLED` and serving `WAITING` → `PREPARING` → `SERVED` (`PUT don-hang/{id}/trang-thai-phuc-vu`), plus a pickup number 1–50 (`PUT don-hang/{id}/so-nhan-mon`) and order editing (`PUT don-hang/{id}`). Stock is deducted only at payment and cancelling never returns stock, so the cancel dialog explains the stock impact per case; the receipt of an unpaid order prints as "PHIẾU TẠM TÍNH"; a yellow banner lists "đơn treo" (PENDING orders created before today, counted at most every 60 s) with a button that filters them. Backend-side business gaps (stock timing, overselling, refund in reports, time zone…) are proposed in `docs/de-xuat-api-nghiep-vu-kho-bao-cao.md`. The backend sync contract is `docs/hop-dong-api-bo-sung.md` (done by the backend on `main`, folder `01-Backend-api`, 18/11/2026).

The API contract (routes, DTO shapes, auth) is agreed with the backend team: keep `Models/` and `api/...` routes in sync with what they expose. **Since 28/11/2026 (owner's decision) we may change backend code in `01-Backend-api/`** when a fix needs it, following `docs/ke-hoach-cai-tien-chuc-nang.md` mục 1.4 (backend's own `CLAUDE.md` order: `openapi.yaml` → DTOs → service/controller → `.http`; DB changes = `QuanCaPheDB.sql` + a patch script; backend commits separate from web commits; list backend changes in the PR).

Relevant installed skills: `dotnet-blazor:*` (components, forms, data fetching, auth), `dotnet:csharp-expert`, `dotnet-test:*`, `ui-ux-pro-max` and `frontend-design` (UI/UX).

## Architecture

- **Entry point**: `Program.cs` registers one `HttpClient` whose `BaseAddress` is `Api:BaseUrl` (falls back to the app's own host), plus a `Scoped` service per domain (`Services/*Service.cs`), `ReportExporter`, and a `Singleton` `AppState`.
- **Services** are thin wrappers over `ApiClient` calling relative `api/v1/...` routes; `HttpClient.BaseAddress` = `Api:BaseUrl` (real backend). **No backend code lives in this repo.**
- **Backend (real API):** `CoffeeShop.Api` (ASP.NET Core 8 + SQL Server `QuanCaPheDB`), API-first, contract = its `openapi/openapi.yaml` (Swagger at `http://localhost:3000/docs`). All routes are under **`api/v1/`** with Vietnamese names (`auth/dang-nhap`, `auth/toi`, `auth/doi-mat-khau`, `nguoi-dung`, `danh-muc`, `kich-thuoc`, `mon`, `mon/{id}/kich-thuoc`, `mon/{id}/con-hang`, `chi-tiet-mon/{id}/cong-thuc`, `topping`, `khuyen-mai`, `don-hang`, `nguyen-lieu`, `nguyen-lieu/{id}/nhap-kho|xuat-huy`, `lich-su-kho`, `bao-cao/doanh-thu|mon-ban-chay|topping-ban-chay|gio-cao-diem`; reports filter revenue by **payment time** `thoiGianThanhToan`). Ids are **ints**; JSON fields are camelCase of the DB columns (`maDonHang`, `tongTien`…); some lists are paged `{ data, meta }` (`mon`, `don-hang`, `lich-su-kho`, limit ≤ 100). Errors are `{ "error": { "code", "message", "details" } }` (message is Vietnamese; 422 `HET_NGUYEN_LIEU` has shortages in `details`). **Unknown fields in a request body → 400**, so request DTOs must match exactly. `wwwroot/appsettings.json` → `Api:BaseUrl: http://localhost:3000/` (CORS is open). Backend sample logins: `quanly` / `QuanLy@123` (QuanLy), `nhanvien` / `NhanVien@123` (NhanVien). Local run: create the DB with `database/QuanCaPheDB.sql` **then `database/FixCongThucUnique.sql`** (otherwise seeding fails on `UQ_CongThuc_Topping`), then `dotnet run` (override the connection string with env `ConnectionStrings__QuanCaPheDB` if not `.\SQLEXPRESS`).
- **Models/** mirror the backend DTOs 1-1 (`NguoiDung`, `Mon`, `GiaTheoSize`, `Topping`, `DanhMuc`, `KichThuoc`, `KhuyenMai`, `NguyenLieu`, `LichSuKho`, `DonHang`, `ChiTietDon`, `BaoCaoDoanhThu`…) plus `*Form` classes for EditForm validation. **Services** use `Services/ApiClient` (JSON in/out, throws `ApiException` whose `Message` is always a user-facing Vietnamese sentence — pages may show it; `Code`/`Details` carry `error.code`/`details`). `Services/Query.Build` builds query strings; date filters send `tuNgay` = 00:00 and `denNgay` = 23:59:59.997 (backend compares with `<=`).
- **No mock API** (removed 2026-11-24, owner's decision): the web always talks to the real backend at `Api:BaseUrl`; test against the running `CoffeeShop.Api` + `QuanCaPheDB`. When the backend contract changes, update `Models/` and the service together.
- The old API contract Claude Doc (https://claude.ai/artifact/4tvnvHxhbnW6GzaAdQY4L1) describes the earlier `api/...` design and is **outdated** — the backend's `openapi.yaml` is now the source of truth.
- **UI/flow overview (reference only):** `docs/Coffee_Shop_Toan_bo_luong_giao_dien (1).pdf` — 61 pages showing the intended screens, flows and business rules (last page = general interaction rules). The owner's decision: it is for **understanding the overall flow**; the **existing pages/UI stay as they are** — do not rewrite pages to match the PDF unless asked. Things explicitly adopted from it: role split owner/staff, account management owner-only, no public registration. (Forgot password via email was dropped on 2026-11-18 — see Auth.)
- **All pages load data through the services** (`OnInitializedAsync`, cancel via a page `CancellationTokenSource` disposed in `Dispose`). Backend constraints reflected in the UI: products are priced **per size** (`PUT mon/{id}/kich-thuoc`), image is a URL string ≤ 255 chars (no upload), delete of món/topping/nguyên liệu is soft (row stays in the table as Ngừng bán / Ngừng sử dụng — stopped items are **not hidden** by default, owner's choice), "Xóa tài khoản" sends `DELETE nguoi-dung/{id}` (backend soft-deletes and frees the username; accounts locked earlier — `trangThai=false`, the web has no lock button — are shown with a "Bị khóa" badge, and Sửa on such an account shows a "Trạng thái" select to unlock, sending `trangThai: true` only then), unpaid unserved orders can be edited, order search sends `timKiem` (order id prefix or exact pickup number), cancel is owner-only with a reason, **no person names anywhere** (owner's decision: no order creator, no payment taker, no inventory actor — the backend still returns `tenNhanVien`/`tenNguoiThu`/`tenNguoiDung`, the web ignores them; only `thoiGianThanhToan` is shown as "Thu tiền lúc"), inventory changes only via nhập kho / xuất hủy, no purchase cost (dashboard has no "chi phí nhập kho").
- **Auth** (`Services/Auth/`): `TokenAuthenticationStateProvider` is the Blazor `AuthenticationStateProvider` — it keeps token/name/role in `AppState` and persists them in `sessionStorage` (`coffeeshop.session`: survives F5, cleared when the tab closes). `AuthenticationService.LoginAsync` calls `api/v1/auth/dang-nhap` (`{ tenDangNhap, matKhau }` → `{ token, hetHan, nguoiDung }`) then `SignInAsync`; `LogoutAsync` signs out. The role and expiry are read from the JWT payload itself (`Services/Auth/TokenClaims`: claims `role`, `exp`; no signature check — the server does that), so editing `sessionStorage` cannot change the menu, and an expired stored token is dropped on F5. `Components/SessionExpiryNotice` (in `MainLayout`) warns ≤ 10 min before expiry and signs out (`byUser: false`, keeps `returnUrl`) when it expires. `AuthHeaderHandler` (wraps the `HttpClientHandler` in `Program.cs`) adds `Authorization: Bearer <token>` to every request and signs out on 401. `App.razor` uses `AuthorizeRouteView` → `RedirectToLogin` (`/login?returnUrl=…`). `Pages/_Imports.razor` puts `[Authorize]` on **every page**; public pages need `@attribute [AllowAnonymous]` (only `/login`). **Role split (owner's requirement):** `QuanLy` (chủ quán, shown as "Quản lý") sees everything; `NhanVien` sees only **Đơn hàng** (`/orders`). Dashboard (`/`), Products, Inventory, Promotions and Accounts are `[Authorize(Roles = Roles.Admin)]`; the sidebar in `MainLayout` renders a different menu per role; staff opening `/` are redirected to `/orders`, other admin pages show "Không có quyền truy cập"; after login staff land on `/orders` (a `returnUrl` to an admin page is ignored for staff — `Login.TargetAfterLogin`). The user name + role in the header (and at the bottom of the phone menu) is **display only** — there is no "my account" page (removed 2026-11-18, owner's decision): passwords are reset by the owner on the Accounts page (Sửa → mật khẩu mới). When adding a page, decide its role and update both the attribute and the menu. Roles are the strings `QuanLy` / `NhanVien` from the backend (`vaiTro`) — use `Utilities/Roles` (`Roles.Admin`, `Roles.Label`, `Roles.HomeUrl`) instead of string literals. The backend enforces roles server-side: staff may read the menu, list/view/pay orders, toggle món/topping availability and read recipes; cancel order, accounts, inventory, reports and menu edits are QuanLy only (403). `GET api/v1/auth/toi` is still used by the Accounts page (to stop the owner deleting their own account); `POST api/v1/auth/doi-mat-khau` exists in the backend but the web no longer calls it.
- **No forgot password / no email in the UI** (owner's decision 2026-11-18: only a few accounts, a forgotten password is reset by the owner on the Accounts page or straight in the DB). The `/forgot-password` page and its models were removed. The Accounts form has **no Email field** and the table no Email column; `email` is optional in the backend, so the web sends `email: null` on create and never sends `email` on PATCH (`NguoiDung.Email` is `string?`).
- **`Components/InputTextLive`**: an `InputText` that updates on every keystroke (`oninput`). Use it for short forms submitted with Enter or browser autofill (login) — plain `InputText` only updates on `change`, so submitting while the cursor is still in the field validates an empty model.
- **Testing note:** with simple sample passwords, Chrome may show its native "password found in a data breach" dialog after login; it silently blocks Playwright clicks/keys (the app is fine — dispatch clicks via `browser_evaluate` or dismiss the dialog).
- **Routing/layout**: `App.razor` defaults to `Layout/MainLayout.razor` (sidebar nav + header). `/login` uses `AuthLayout`. The header title comes from a URL→title `switch` in `MainLayout` — when adding a page, add its nav link **and** its title mapping there.
- **Pages** live in `Pages/<Feature>/`. Bigger pages split logic into a `.razor.cs` partial class using `[Inject]` properties; others keep everything in an `@code` block (Orders.razor is >1000 lines).
- **Shared components** (`Components/`): `Icon` (inline SVG looked up by `Name` from an internal path dictionary — add new icons there), `Modal` (dialog with backdrop/Escape close), `Brand`, and the list-page building blocks below.
- **Management-page pattern (owner's requirement — keep every list page the same):**
  - Toolbar = `CrudActions`: **Thêm · Sửa · Xóa** on every management page (same order/style; Sửa/Xóa need a selected row, `DeleteBlockedReason` disables Xóa with a tooltip), then page-specific buttons as `ChildContent` (Công thức, Nhập / xuất hủy). No separate status buttons (no "Ngừng bán", "Báo tạm hết", "Khóa").
  - Status of a record is edited in the **Sửa** form with an `InputSelect` labelled "Trạng thái" (Kho, Món, Topping); the **Thêm** form has no status field (new records start active).
  - Filter bar: search box + `filters-toggle` "Bộ lọc (n)" (≤1000px) + `RefreshButton` (dot when filtering/searching/sorting; resets everything and reloads) + `filter-extra` with `filter-break`/`filter-half` selects. Default filters show **all** records, including stopped ones.
  - Search is accent/case-insensitive via `Utilities/SearchText` (`Fold` once, `Contains` per field); ids match as digit substrings. Orders keeps its digits-only search.
  - Sortable columns use `Utilities/ColumnSort` + `Components/SortHeader`; empty tables use `Components/EmptyRow` (with "Bỏ lọc" when filtering). 10 rows per page (Orders 20). Tables collapse secondary columns into `.stock-sub` lines on narrow screens (CSS sections [11]–[13]). `Selected` only resolves among visible rows.
- **Editing pattern**: forms edit a separate `*Form` object and send a request DTO on save; `Utilities/ModelCopy` (JSON deep copy) is still available. Number fields (`InputNumber` price / quantity / percent) carry `min="0"` so the spinner stops at 0 (owner 2026-11-25), and their `EditForm` has `novalidate` so the browser's English bubbles don't block submit — the Vietnamese `[Range]` / page checks reject negatives.
- **Promotion status** (`TrangThaiKhuyenMai`): only Đang áp dụng · Chưa bắt đầu · Đã kết thúc, by date range. "Ngoài khung giờ" was dropped 2026-11-25 (a transient in-range state outside golden hours); it now shows as a small "Ngoài giờ vàng lúc này" note in the Giờ vàng column.
- **Export** (Dashboard "Xuất Excel", owner's decision 2026-11-23: Excel only, no CSV/PDF): `ReportExporter.Build` fills a 4-sheet `.xlsx` data report (Tổng hợp · Doanh thu theo giờ/ngày/tháng · Món bán chạy · Topping bán chạy; header = shop name from `Receipt:*`, exact report period, creation time; **no formula-explanation text** — owner's decision) via `Utilities/XlsxWriter` — a dependency-free Office Open XML writer on `System.IO.Compression` (real numbers `#,##0 đ`, real dates, `0.0%` shares only on Tổng hợp and Món bán chạy, `SUM`/`IF` formulas, frozen headers); the bytes go to `window.appHelpers.downloadFile(name, bytes, mime)` in `wwwroot/js/app.js`. Blazor caches JS function lookups, so override that helper before the first click when testing. Dashboard card "Doanh thu thuần" = sum of PAID orders by payment time (prices already after promotion, refunds excluded); default filter is "Hôm nay" (`DatePresets.Options` / `DatePresets.Default`, which has no "Tất cả thời gian" — owner's decision; since 2026-11-25 Orders and Inventory history use the same list and default: Hôm nay · 24 giờ · 7 ngày · 30 ngày · Chọn khoảng ngày…, 7/30 days = calendar days incl. today); the average-order card has no sub-line.
- **Styling**: all styles are in one global stylesheet, `wwwroot/css/app.css` (no scoped `.razor.css` is loaded — `index.html` doesn't link the scoped bundle). It starts with a **design-token** `:root` block (`--coffee-50…800`, `--ink`/`--muted`, `--line`, status pairs like `--success`/`--success-bg`, `--r-sm/md/lg/pill`, `--shadow-*`, `--focus-ring`, `--fs-*`, `--ease`); use these tokens, never raw hex. The "TINH CHỈNH GIAO DIỆN" block at the end holds interaction states (hover/focus/disabled), badge/table/pagination polish and mobile/reduced-motion rules. Font: Be Vietnam Pro via Google Fonts (falls back to Segoe UI); the logo SVG keeps Segoe UI on purpose.
- **Cache busting**: `index.html` links `css/app.css?v=N` and `js/app.js?v=N` — bump `N` whenever that file changes, otherwise browsers keep the old copy (a stale `app.js` makes new JS-interop calls throw and crash the render with "Có lỗi xảy ra"). Wrap non-essential JS-interop calls in `try/catch (JSException)`.
- **Culture**: the csproj sets `BlazorWebAssemblyLoadAllGlobalizationData` so `vi-VN` formatting works (`29.000 đ`); without it WASM silently falls back to `29,000`.

## Coding rules

Follow these when writing code (existing code still violates some — fix them when touching that code):

- Never show `ex.Message` / `exception.Message` to users; show a fixed Vietnamese message and log details via `ILogger`.
- Components that subscribe to events (`NavigationManager.LocationChanged`, `AppState.OnChange`) or create `Timer`/`CancellationTokenSource` must implement `IDisposable`/`IAsyncDisposable` and unsubscribe/dispose.
- Load data in `OnInitializedAsync`; update UI from timers/background threads via `InvokeAsync(StateHasChanged)`; disable submit buttons while saving.
- Status/role strings come from the backend and live in ONE place each: `TrangThaiDon` (`PENDING`/`PAID`/`CANCELLED` + Vietnamese `Label`), `PhuongThucThanhToans` (`CASH`/`QR_TRANSFER`; payment column colour = `Tone`, method shown only when `DaChot`), `TrangThaiPhucVus` (`WAITING`/`PREPARING`/`SERVED`, `Label`/`Tone`), `LoaiGiaoDichKho`, `TrangThaiMon` (display status computed from `ngungBan`/`conHang`/`coTheBan`), `TrangThaiKhuyenMai`, `LocSuDung`, `TinhTrangKho`, `Roles` — never write these literals in pages.
- Put styles in `wwwroot/css/app.css` using the design tokens — not new inline `style="..."`, and not a `.razor.css` (the scoped-CSS bundle isn't linked in `index.html`, so it would have no effect). Bump `app.css?v=N` in `index.html` after editing.
- Any change to an `api/...` route or DTO shape: flag that the API contract doc / backend team needs updating.

## Review workflow

Project subagents live in `.claude/agents/` (read-only reviewers; they report, the main agent fixes):

- **`code-reviewer`** — project-specific code review (API contract sync, Blazor patterns, status strings, conventions).
- **`ui-ux-reviewer`** — runs the app with Playwright, screenshots at 3 widths, reads the console, checks accessibility and the order flow.

Standing rule (superseded/strengthened by "Quy trình bắt buộc" above): after **every** feature change or fix, run `code-reviewer`; if it touched UI or a user flow, also run `ui-ux-reviewer`. Then fix confirmed issues and report. Only trivial text/typo edits may skip this. Don't run `ui-ux-reviewer` while the user is debugging on port 5101 unless they agree.
